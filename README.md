# 星海 FM · 本地有声书播放器

把本地文件夹变成一座私人音频图书馆：自动整理成专辑、自由分类、倍速播放、全离线。
界面是深空霓虹风格，音频永远留在本机，没有任何联网请求。

## 三种打开方式

| 方式                | 适用      | 说明                                               |
| ----------------- | ------- | ------------------------------------------------ |
| **桌面版 exe（推荐）**   | Windows | 双击 `dist\星海FM-1.0.0.exe`，免安装；首次选一次目录，之后自动记住并自动同步 |
| **启动.bat**        | 浏览器     | 起一个本地服务器（localhost:8080），浏览器打开；可以记住目录授权          |
| **双击 index.html** | 临时用     | 直接以 file:// 打开，功能齐全，但每次重开要重新选目录（浏览器限制）           |

### 桌面版

1. 双击 `dist\星海FM-1.0.0.exe`（约 360 MB，单文件，免安装；不压缩打包，启动更快）
2. 点左上角「选择资源库」，选到有声书所在文件夹（例如 `E:\迅雷下载\output`）
3. 扫描完成后即可使用；下次启动自动恢复资源库与上次播放位置
- 目录路径记在 `%APPDATA%\星海FM\config.json`
- 分类、收藏、播放进度记在该目录下的浏览器存储（Electron LocalStorage）
- 首次运行若出现 Windows SmartScreen 提示，点「更多信息 → 仍要运行」即可（未做代码签名）

## 功能

- **资源库**：一个目录就是一个资源库，可以加多个（比如「有声书」「课程」「广播剧」），侧栏一键切换
- **目录即专辑**：资源库里每个顶层子目录自动成为一个专辑，按集号自然排序（第2集排在第10集之前）
- **专辑封面**：跑一次 `node tools/fetch-covers.js`，按目录名去喜马拉雅搜同名专辑并下载封面，存进音频目录的 `.fm-covers/`；卡片、详情页、播放页、系统媒体信息都用真封面，搜不到才退回渐变封面
- **自动去重**：同名文件（例如 `mp3/` 子目录里的低码率副本）只保留体积最大的一个
- **智能分类**：首次扫描按关键词自动归入 历史军事 / 文学小说 / 心理成长 / 国学经典 / 影视原声，可自由增删改
- **分类管理**：新建、换色、重命名、删除；**把专辑卡片直接拖到左侧分类**即可归类，一个专辑可属于多个分类
- **收藏 / 置顶 / 隐藏 / 重命名**：专辑卡片或详情页的「更多」菜单
- **继续收听 / 最近播放 / 已听完标记**：自动记录每一集的播放位置，最多 4 秒内落盘
- **播放器**：0.5×–3× 倍速（保持音调）、进度拖动、上一集/下一集、列表循环 / 单集循环 / 随机 / 顺序、定时关闭、音量
- **全屏播放页**：实时频谱、大封面、15 秒快进快退、播放队列
- **视频播放**：目录里的 mp4 / webm 也能直接看，播放页自动切成 B 站式画面 + 浮层控件（详见下面「视频」）
- **系统媒体键**：支持键盘媒体键与锁屏信息
- **离线**：全站无外链、无字体 CDN、无埋点

## 资源库

一个资源库 = 一个目录。想放两类内容就加两个库，随时切换，不用来回选目录。

- **切换**：点侧栏最上面那块（当前库名）→ 弹出库列表 → 选一个就切过去。有缓存的库秒开，同时后台补扫新加的文件
- **管理**：同一菜单里的「资源库设置…」，或者空库时的「添加资源库」按钮
  - 添加资源库：选一个文件夹，加进列表并立即切过去扫描
  - 重命名：只改显示名，不动路径
  - 重新定位：目录被改名 / 换盘时用，选中新位置即可，分类和收藏不丢
  - 在文件夹中打开：直接弹出系统文件管理器，方便往里丢新书
  - 移除资源库：**只移除列表项**，文件夹、分类、收藏都留在本机；以后把同一目录加回来还是原样
- **分类和收藏按库隔离**：两个库里有同名专辑也互不干扰；**播放进度按相对路径全局共享**，同一本书放在两个库里也只记一份进度
- **切库会停止播放**：进度已经落盘，切回来点一下就能续播
- **目录不见了**（改名、移动、移动硬盘没插）：侧栏那块会标红，首页给出「重新定位 / 切换资源库」两个按钮

桌面版的库列表存在 `%APPDATA%\星海FM\config.json`（旧的 `{ "root": ... }` 配置会在首次启动时自动升级成一条资源库）；网页版存在浏览器本地，目录句柄在 IndexedDB 里。分类、收藏、播放进度这些「整理结果」除了浏览器存储，还会同步一份到每个库目录下的 `.fm-meta.json`（见下面「远程同步」）。

## 视频

视频和音频共用同一个资源库、同一条播放链路：扫描时就按扩展名认出来，列表行带「视频」角标，专辑卡片显示视频集数；点开视频集自动进入播放页的视频模式（启动时恢复上次进度不会自动弹页）。

**收录格式**：`mp4 / m4v / mov / webm / ogv`（Chromium 能直接解的容器）。`mkv / avi / flv / rmvb` 照旧跳过，不做转码；确实要看可以先用 ffmpeg 换个壳：

```bash
ffmpeg -i 某剧集.mkv -c copy 某剧集.mp4     # 只换容器，几秒钟
```

**播放页（B 站式）**

| 操作 | 行为 |
| --- | --- |
| 单击画面 | 播放 / 暂停（暂停时中央有大播放键） |
| 双击画面 | 影院模式开 / 关 |
| 鼠标静止约 2.6 秒 | 顶部信息 + 底部控件淡出、光标隐藏；动一下就回来 |
| 底部进度条 | 悬停看时间点、可拖动，已缓冲部分高亮 |
| 选集 | 右侧滑出本专辑的集数列表，点一条直接切；面板展开时画面会让出宽度 |
| 画中画 / 影院 / 全屏 | 右下角三个按钮，分别对应系统小窗、贴边铺满、原生全屏 |
| 切回音频集 | 画面收起，封面 + 频谱照旧 |

倍速、音量、静音、定时关闭、断点续播在视频里同样生效。

## 专辑封面

封面不是在应用里联网抓的，而是先用脚本抓到本地，播放器只读本地文件——所以界面上依旧没有任何外链请求。

```bash
node tools/fetch-covers.js                       # 默认抓 E:\迅雷下载\output
node tools/fetch-covers.js --root "D:/有声书"     # 换目录
node tools/fetch-covers.js --only 三体            # 只补某几本
node tools/fetch-covers.js --force               # 全部重抓
```

- 抓取结果放在音频目录的 `.fm-covers/`：图片 + 一份 `covers.json`（目录名 → 图片文件、匹配到的专辑标题、相似度）
- 目录名就是喜马拉雅上的专辑标题时基本能精确命中；差一点点也能靠相似度匹配上，两边都会记录匹配度
- 已经抓过的会自动跳过，新加几本书再跑一次就行
- 播放器侧按目录名精确匹配，再按相似度（≥0.8）复用；换了名字的同名专辑会共用同一张封面

### 手工指定封面：`.fm-covers/manual.json`

少数专辑搜不到（或者搜到的是别的版本）时，脚本会把候选和最高相似度列出来。确认后把「目录名 → 专辑页」写进音频目录下的 `.fm-covers/manual.json`，再跑一次脚本即可：

```json
{
  "抗美援朝战争全史": "https://www.ximalaya.com/album/39246532",
  "三体 有声书全本无删减 王明军单播 刘慈欣原著": "40121646",
  "某张只能找到图的书": "https://imagev2.xmcdn.com/group82/M01/06/3C/wKg5Il70GkGy2c7HAAHU2k3a36c730.jpg"
}
```

- **专辑页地址 / 纯数字 id**：喜马拉雅专辑页（`www.ximalaya.com/album/<id>`）是前端渲染的，封面来自页面自己请求的 `/revision/album/v1/simple?albumId=<id>`；脚本打的就是这个接口，同时取回专辑标题并记下相似度（写死的 id 不做阈值拦截）
- **封面图片地址**：直接下载，自动去掉 `!magick=webp` 这类转换参数、补 600×600 缩放；不再搜索、也不做相似度判断
- 键必须和专辑目录名**完全一致**（脚本输出里会打印目录名）。`manual.json` 里写死的条目在 `--force` 时也照样生效

## 开发与打包

```bash
npm install            # 安装 electron / electron-builder
npm start              # 启动桌面版（开发模式）
npm run dist           # 打包到 dist/：便携版 exe + 安装版 Setup exe
npm run dist:mac       # macOS：出 dmg + zip（arm64 / x64），必须在 Mac 上跑
```

**版本号自动递增**：每次 `npm run dist` / `dist:mac` / `pack:mac` 之前，会把 `package.json` 的小版本号 +1（`1.0.0 → 1.0.1`），`package-lock.json` 一起同步，产物名跟着变（`星海FM-1.0.1.exe`、`星海FM-1.0.1-arm64.dmg`）。逻辑在 `tools/bump-version.js`，由 `predist` / `predist:mac` / `prepack:mac` 钩子自动调用；只想涨版本不打包就 `npm run bump`，想不涨版本打一次就 `SKIP_BUMP=1 npm run dist`。

**两种 Windows 产物别用错**：

- `星海FM-<版本>-Setup.exe`：安装版（单用户装到 `%LOCALAPPDATA%\Programs`，桌面/开始菜单有快捷方式）。装完从硬盘直接启动，实测到主页面约 3 秒。
- `星海FM-<版本>.exe`：便携单文件，免安装，但每次双击都要把 ~360MB 解包到临时目录再启动，实测到主页面约 10 秒。只适合临时拷给别人试。

### macOS 部署包

- **源码包**：`dist/XinghaiFM-1.0.0-src.zip`，解压后 `npm install && npm start` 即可运行
- **公网隧道**：解压后双击 `启动-公网.command`（Windows 上是 `启动-公网.bat`）；两者都是读 `.tunnel.json` 起 `tools/tunnel.js`，先用 `node tools/serve.js --set-password` 设口令
- **出安装包**：解压后双击 `打包-macOS.command`，或在终端 `npm run dist:mac` → `dist/` 里的 dmg/zip
- 已配好：应用图标 `build/icon.icns`、分类 `public.app-category.music`、macOS 应用菜单（`main.js` 的 `setupMenu()`）、最低系统 macOS 12.7.6（Monterey；Electron 锁定 42.11.18 就是为了这个）
- 没有开发者证书时 electron-builder 会做 ad-hoc 签名，对方首次打开需要「右键 → 打开」放行

**为什么不在这台 Windows 上直接交叉打 .app**：macOS 的 `.app` 里 `*.framework` 依赖一堆符号链接（`Versions/Current` → `A`），而且内容一改就要重新代码签名。Windows 侧打 zip 会把符号链接压成普通文件、也做不了 `codesign`，产物在 Mac 上大概率启动失败——所以只给源码 + 一条命令的打包脚本。

桌面版与网页版共用同一套前端代码，区别只在 `js/fs.js` 的取文件通道：

| 运行环境              | 通道                                                              |
| ----------------- | --------------------------------------------------------------- |
| Electron          | `fmNative` 原生对话框选目录 → 主进程扫描 → `fm://app/__media/…` 按 Range 流式播放 |
| localhost / https | File System Access API，目录句柄存 IndexedDB，刷新免重选                    |
| file://           | `<input webkitdirectory>`，每次需重选目录                               |

桌面版音频由 `fm://app/__media/` 协议按 Range 直读磁盘（不把整本有声书读进内存），网页版走 `File → blob URL`；两条通道都直连 `<audio>`，所以拖动进度瞬时响应，频谱也能拿到真实波形。

## 远程访问（可选）

想让手机或别的电脑听这台机器上的书，用「服务器模式 + SSH 反向隧道」。音频由本机的 `tools/serve.js` 直接托管，支持拖动进度（HTTP Range）。

1. **先设访问口令**（只存 pbkdf2-sha256 60 万轮哈希到 `.auth.json`，明文不进文件、也不进 URL；重设会顺带踢掉所有已登录设备）：

   ```bash
   node tools/serve.js --set-password 你的口令
   ```

2. **只在本机试**（不开隧道）：

   ```bash
   node tools/serve.js 8080                        # 读桌面端的库列表（多目录）
   node tools/serve.js 8080 --config /srv/fm/config.json   # 服务器上没有桌面端时用这份
   ```

   打开 `http://127.0.0.1:8080/`，会先跳到登录页，口令对了才进资源库（不用再授权目录）。

3. **挂到公网服务器**：把 `.tunnel.example.json` 复制成 `.tunnel.json`，填 `ssh.host`（`ssh.key` 留空就用默认的 `~/.ssh/id_rsa`）。库列表默认读桌面端的 `config.json`，服务器上没有桌面端就在 `configFile` 里写另一份的路径。然后双击 `启动-公网.bat`：

   ```
   清理服务器上残留的 8889 监听…
   访问地址  http://<你的服务器地址>:8889/
   ```

   登录固定是 `root` + 密钥，不会弹密码（密钥没配好会直接报错）。启动前会先 `ssh root@host "fuser -k 8889/tcp"` 清掉上次异常断开残留的远端监听——否则新隧道会绑定失败。

### 远程同步（远程只读镜像 + 进度双向）

桌面端会把整理结果写进每个资源库目录下的 `.fm-meta.json`，服务端直接从这份文件读：

| 数据 | 方向 |
| --- | --- |
| 分类定义、分类归属、收藏、专辑改名 | 桌面 → 远程（远程界面禁止编辑，点了提示「远端只读」） |
| 时长 | 桌面 → 远程 |
| 播放进度 | 桌面 ⇄ 远程，逐条按时间戳取新的那条 |

- 桌面端有改动后约 5 秒写一次文件；手机播放时每 10 秒推一次进度（暂停 / 切集 / 关页面时立即推）
- 桌面启动、以及窗口重新获得焦点时，会把文件里更新的进度合并回本地
- 远程可以切换资源库：服务端读桌面端的 `config.json`，通过 `/api/libs` + `/api/activate` 暴露
- `.tunnel.json` 的 `configFile` **留空** = 读桌面端的 `config.json`；填了就用那份（多目录写在它的 `libs` 里）
- **断线自动重连**：隧道掉线后按 3 秒 → 6 秒 → 9 秒…（最长 30 秒）自动重试，连上并稳定 20 秒后重新计时；连续两次「刚连上就断」会先清一次服务器上的残留 8889 监听。`Ctrl+C` 仍然是手动退出
- **重连上限**：`.tunnel.json` 的 `maxRetries`（默认 10，**0 = 不限次数**）；临时改可以用 `node tools/tunnel.js --max-retries 3`。到上限后进程退出，重新双击 bat 即可再来
- 服务端也可以手动指定配置：`node tools/serve.js 8080 --config "C:/Users/你/AppData/Roaming/星海FM/config.json"`

**安全开关**

- **远程增删资源库默认关闭**。要让网页上能「添加资源库 / 重命名 / 移除资源库」，服务端启动时要加 `--allow-lib-edit`（隧道模式在 `.tunnel.json` 里写 `"allowLibEdit": true`，`启动-公网.bat` 会带过去）。不开的话网页只能切库，列表是只读的
- 即使开了，也**不能把磁盘根目录加成资源库**（会直接拒绝）
- `/api/media` 只放行媒体扩展名（mp3 / m4a / flac / mp4 / webm…），其它文件一律 404——否则把它当成资源库根目录的通用读文件接口，就能读到 `config.json`、`id_rsa` 这类东西
- 远程增删库会在服务端控制台打一行日志（`[lib] 远程添加资源库：…`），方便事后核对

4. 服务器侧还需要两件事（脚本改不了）：
   - `/etc/ssh/sshd_config` 里 `GatewayPorts clientspecified`（否则 8889 只绑在服务器的 127.0.0.1，得再加 nginx/caddy 反代）
   - 云安全组放行 8889

说明：登录成功后种的是 HMAC 签名的会话 Cookie（HttpOnly / SameSite=Lax），7 天不用就失效，但从首次登录算起最多续到 30 天；活跃时每 6 小时重签一次，常用不掉线。静态资源和 `/api/*` 都靠它；没有会话时页面 302 到登录页、接口 401。同一 IP 10 分钟内错 5 次会锁 10 分钟。旧口令文件在下次登录时会自动升到 60 万轮（secret 会换，其他设备需重登一次）。静态文件只放行 `index.html / css / js / build`，源码和 dist 访问不到；带 ETag（`cache-control: no-cache`），没改就回 304；文本类（html/css/js/json）按 `accept-encoding` 走 gzip，音频和封面不压（本来就压过）。

### 桌面客户端直连远程服务器（不走浏览器）

上面那套是给手机/浏览器用的。桌面客户端也可以把数据源指到远端：界面仍是本机的（秒开、不依赖网络启动），书和音频留在服务器上。

1. 服务器上起服务（默认读桌面端的库列表，多目录）：

   ```bash
   node tools/serve.js 8080
   ```

2. 桌面端：侧栏「资源库」→ **连接远程服务器…** → 填地址 `http://192.168.1.8:8080`（不要带末尾斜杠）+ 访问口令 → 连接。成功后界面自动重载，库列表、扫描、封面、播放、进度回写全部走远端。

3. 断开：同一个入口会变成 **远程服务器设置…**，点「断开连接」，重载后回到本地资源库模式。

要点：

- 配置存在 `%APPDATA%\星海FM\remote.json`（macOS：`~/Library/Application Support/星海FM/remote.json`），内容是 `{ base, token }`。**token 等同口令**，别外发；服务端重设口令后要重连一次
- token 走 `Authorization: Bearer`，只有桌面端请求头里带；`<audio>` / `<img>` 带不了请求头，改用 `GET /api/ticket` 换 2 小时的短期票据挂在 `?t=` 上（长期 token 不落进 URL）
- 服务端已放开跨源（`Access-Control-Allow-Origin: *` + 预检放行），因为桌面端页面来自 `fm://app`
- 远程模式下资源库列表只读：不能添加 / 重命名 / 重新定位，这些只能在跑服务的那台机器上做
- 侧栏会标「远程 · N 个资源库」，库徽标右下角的小圆点表示链路状态（绿色在线 / 琥珀色掉线）；资源库设置抽屉里每行显示「远程资源库」，底部那颗按钮就是服务器地址，点进去可以改地址或断开
- 服务器上没有桌面端（比如 Linux VPS）时，自己写一份 `config.json` 用 `--config` 指过去，`libs` 就是多目录：

  ```json
  {
    "active": "a",
    "libs": [
      { "id": "a", "name": "有声书", "path": "/data/books/audio" },
      { "id": "b", "name": "播客",   "path": "/data/books/podcast" }
    ]
  }
  ```

  ```bash
  node tools/serve.js 8080 --config /srv/fm/config.json
  ```

  改这个文件不用重启服务，服务端按 mtime 每秒检查一次。多目录就是在 `libs` 里多写几条。
- **明文 http 只建议局域网或 SSH 隧道**；走公网请套一层 https 反代，或者直接用前面说的隧道方案
- **断线自动重连**：掉线后顶栏出现「离线，正在重连…」，按 3 → 6 → 9 → 15 → 30 秒退避重试（封顶 30 秒）；恢复后自动提示「已重新连接」并补刷一次。开机时服务器就不可用的话也一样，等它回来会自动重载进库列表
- token 失效（服务端重设过口令）不会无限重试，顶栏会变成「远程未授权，点此重连」，点一下回到连接对话框

## 配置参考

### 文件都在哪

| 文件 | 位置 | 作用 | 能不能删 |
| --- | --- | --- | --- |
| `config.json` | 桌面版：`%APPDATA%\星海FM\`（macOS：`~/Library/Application Support/星海FM/`） | 资源库列表 + 当前选中的库 | 删了等于清空库列表，音频不受影响 |
| `.fm-meta.json` | **每个资源库目录内** | 分类定义 / 分类归属 / 收藏 / 改名 + 播放进度 / 时长 | 删了会重建，但远程端会暂时看不到分类 |
| `.fm-covers/covers.json` | 每个资源库目录内 | 专辑封面索引（`tools/fetch-covers.js` 生成） | 删了只是没封面 |
| `.tunnel.json` | 项目根目录 | 公网隧道配置 | 删了 `启动-公网.bat` 会提示缺配置 |
| `remote.json` | 桌面版 userData 目录（同 `config.json`） | 远程后端地址 + 长期 token（**等同口令，别外发**） | 删了等于断开远程，回到本地模式 |
| `.auth.json` | 项目根目录 | 访问口令的 pbkdf2 哈希（**不是明文**） | 删了要重新 `--set-password` |

桌面版的 localStorage（分类、收藏、进度、索引缓存的「主副本」）在 `%APPDATA%\星海FM\Local Storage\leveldb`，是浏览器存储，不用手工改；它和 `.fm-meta.json` 的关系见上面「远程同步」。

### `.tunnel.json`

复制 `.tunnel.example.json` 改，字段：

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `configFile` | 自动 | 让服务端读另一份 `config.json`（服务器上没有桌面端时用） |
| `allowLibEdit` | `false` | 是否允许在网页上增删 / 重命名资源库（对应 serve.js 的 `--allow-lib-edit`） |
| `maxRetries` | `10` | 断线自动重连上限；**`0` = 不限次数**（每 30 秒试一次） |
| `localPort` | `8080` | 本地服务端口 |
| `remotePort` | `8889` | 服务器上对外暴露的端口 |
| `ssh.host` | — | 服务器地址（必填） |
| `ssh.port` | `22` | SSH 端口 |
| `ssh.key` | `""` | 私钥路径，留空用 `~/.ssh/id_rsa` |
| `configFile` | 自动 | 想让服务端读另一份桌面配置时填路径 |

### 桌面端 `config.json`

```json
{
  "libs": [
    { "id": "l1abcd", "name": "喜马拉雅mp3", "path": "E:/学习资料/喜马拉雅mp3", "addedAt": 1793005585609 }
  ],
  "active": "l1abcd"
}
```

- 老版本的 `{ "root": "..." }` 会在首次启动时自动升级成一条资源库，不用手工迁移
- 写入是「先写 `.tmp` 再 `rename`」的原子操作；桌面端和服务端都按文件 mtime 判断要不要重读——**任何一方改了，另一方最多 1 秒内生效**，不用重启
- 服务端只读这份文件，只有开了 `allowLibEdit` 才会通过 `/api/lib` 往里写

### `tools/serve.js` 启动参数

| 参数 | 说明 |
| --- | --- |
| `<port>` | 端口，默认 8080 |
| `--config <file>` | 指定桌面端配置路径（默认自动找 `%APPDATA%\星海FM\config.json`） |
| `--allow-lib-edit` | 允许远程增删资源库（默认关） |
| `--host <ip>` | 监听地址，默认 `127.0.0.1` |
| `--no-auth` | 关掉口令校验，只在本机调试用（会跳过登录页） |
| `--set-password <口令>` | 设置 / 重设访问口令（写进 `.auth.json`） |
| `--check-password` | 校验当前口令 |

`启动-公网.bat` 会自动拼：`<localPort> --host 127.0.0.1 [--config <file>]`，再按 `.tunnel.json` 决定加不加 `--allow-lib-edit`。

### `tools/tunnel.js` 参数

| 参数 | 说明 |
| --- | --- |
| `--max-retries <n>` | 临时覆盖 `.tunnel.json` 的重连上限（`0` = 不限） |

### 服务端接口速查

都需要登录会话（`--no-auth` 除外）：

| 接口 | 说明 |
| --- | --- |
| `GET /api/config` | `{ server, rootName, multi, libEdit }` |
| `GET /api/libs` | 资源库列表 + 当前库 |
| `GET /api/activate?id=` | 切换当前库（服务端内存态） |
| `GET /api/meta` | 当前库的 `.fm-meta.json` |
| `POST /api/progress` | 手机回传播放进度，按时间戳合并 |
| `POST /api/lib` | 增 / 删 / 改名资源库（需 `--allow-lib-edit`） |
| `POST /api/login` | 口令换长期 token（桌面端连接用），返回 `{ token }` |
| `GET /api/ticket` | 换 2 小时短期票据，给 `<audio>` / `<img>` 的 `?t=` 用 |
| `GET /api/scan` | 目录列表 |
| `GET /api/media/<rel>` | 音频流（支持 Range），**只放行媒体扩展名** |
| `GET /api/covers` · `/api/cover/<file>` | 封面索引与图片 |

## 常见问题

**Q：某集点了没声音？**
文件可能已被移动或删除，点侧栏的刷新按钮重新扫描。

**Q：想换一个文件夹？**
点侧栏顶部的资源库按钮切换，或在「资源库设置」里添加 / 重新定位。旧库的分类记录会保留，只对各自的库生效。

**Q：原来那个单目录配置还能用吗？**
能。老的 `{ "root": "..." }` 配置在首次启动时会**自动升级成一条资源库**（名字取目录名），分类和收藏一起搬过去，不用重新选目录。

**Q：视频点了没反应 / 只有声音？**
容器对了但编码不对（例如 HEVC、H.265）。换 H.264/AAC 的 mp4，或按上面那条 ffmpeg 命令转一次。

**Q：播放进度会丢吗？**
桌面端主副本在 localStorage（`%APPDATA%\星海FM\Local Storage`），同时每 5 秒左右落一份到库目录的 `.fm-meta.json`——**连库目录一起备份就等于备份了进度**。

注意分类 / 收藏的主副本是 localStorage，`.fm-meta.json` 里那份是给远程端读的，桌面端不会自动从它恢复这一类信息；换电脑想全带走，请备份整个 `%APPDATA%\星海FM\` 目录。

**Q：桌面端加了资源库，网页上没看到？**
服务端按 `config.json` 的 mtime 热加载，最多 1 秒就生效；页面切回来或刷新时会重新拉列表。还看不到就确认网页访问的是同一台机器上的服务（`/api/config` 里的 `multi` 应该是 `true`）。
